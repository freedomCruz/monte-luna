# Feature: deploy-v1

First production-grade deployment of the Monteluna storefront and Go API to the hardened Contabo VPS at `montelunaco.com`: audited Docker install, Compose stack (Caddy, Go API, PostgreSQL 18), the project deploy script with health-checked automatic rollback, and independent backups with a restore drill. Branch `feat/deploy-v1` (based on `feat/vps-hardening-v1`); nothing is pushed without explicit authorization.

### S3: Approved deployment flow (canonical, `system-architecture.md` §6)
Preflight (clean tree, existing `vX.Y.Z` tag, local CI gates) → build Go and Caddy images in Linux containers tagged with version and SHA → `docker save | ssh docker load` → pre-deploy `pg_dump -Fc` → goose migrations (expand → migrate → contract) → `docker compose up` with per-service memory limits → health check on `GET /api/v1/health` with automatic rollback of both images to the previous tag → record the active release. Never build on the VPS; secrets in a `0600` env file outside Git.

## Design (coordinator)

- Only Caddy publishes host ports (80, 443). PostgreSQL and the Go API publish no ports and live on an internal Compose network: Docker-published ports bypass UFW (documented by Docker), so an unpublished port is the only reliable way to keep them private.
- UFW additionally allows 80/tcp and 443/tcp for clarity and for Caddy's ACME HTTP challenge.
- Every service sets `mem_limit` and an equal `memswap_limit`, so containers cannot consume host swap.
- The Caddy admin API stays bound to localhost inside its container and is never published.
- The Go module must build with the audited Go 1.27.3 toolchain (`chore/go-1.27.3`, user-approved security exception) because 1.27.2 triggers reachable `GO-2026-6809`.
- Identity and Notifications are not on this base yet; when they ship they deploy together (existing decision).

Always reference `name:tag@digest`.
- **Release id**: `<vX.Y.Z>-<7-char SHA>`, exported to Compose as `MONTELUNA_RELEASE`. Images: `monteluna-api:${MONTELUNA_RELEASE}` and `monteluna-caddy:${MONTELUNA_RELEASE}`, built `--platform linux/amd64`, always deployed and rolled back together.
- **API image** (`backend/Dockerfile`, context `backend/`): `CGO_ENABLED=0 go build -mod=readonly -trimpath` of `./cmd/api` to `/app/api` and `./cmd/migrate` to `/app/migrate` on the distroless `nonroot` runtime; `ENTRYPOINT ["/app/api"]`; `API_ADDR=:8080`. `backend/.dockerignore` excludes tests, local env files, and VCS data.
- **Caddy image** (`deploy/caddy/Dockerfile`, context = repository root): stage 1 builds the minimal module in `deploy/caddy/` (`main.go` calling `caddycmd.Main()` with the standard modules import; `go.mod`/`go.sum` pinning `github.com/caddyserver/caddy/v2 v2.11.7` and `golang.org/x/net v0.60.0`; `govulncheck` clean); stage 2 builds `frontend/` with `npm ci` and `npm run build` using npm 12.2.0 as pinned by `devEngines` and a build argument `CATALOG_API_URL` passed through unchanged (see D1); stage 3 is distroless `nonroot` with `/usr/bin/caddy`, `/etc/caddy/Caddyfile` from `deploy/caddy/Caddyfile`, static files in `/srv`, and `/data` and `/config` owned by `65532:65532` with `XDG_DATA_HOME=/data` and `XDG_CONFIG_HOME=/config`. A root `.dockerignore` keeps `node_modules`, `.astro`, `dist`, `test-results`, env files, and `.git` out of the build context.
- **Caddyfile**: site address `{$SITE_ADDRESS}`, ACME email `{$ACME_EMAIL}`; `encode zstd gzip`; `handle /api/*` → `reverse_proxy api:8080`; everything else → `root * /srv` + `file_server` (`precompressed` allowed); `handle_errors` serves `/404.html` for 404; security headers (`Strict-Transport-Security`, `X-Content-Type-Options nosniff`, `Referrer-Policy strict-origin-when-cross-origin`, `X-Frame-Options DENY`); admin API stays on its localhost default and is never published.
- **Compose** (`deploy/compose.yaml`, project name `monteluna`): services `caddy`, `api`, `postgres`. Networks: `web` (caddy, api; normal bridge so the API can reach Wompi) and `db` (`internal: true`; api, postgres). Only `caddy` publishes `80:80`, `443:443`, and `443:443/udp`, with `sysctls: net.ipv4.ip_unprivileged_port_start: 0` because it runs as non-root. Volumes `pgdata` (mounted at `/var/lib/postgresql`, PostgreSQL 18 image layout), `caddy_data` (`/data`), `caddy_config` (`/config`). Memory: postgres `2g`, api `512m`, caddy `256m`, each with an equal `memswap_limit`. `restart: unless-stopped`. PostgreSQL health check `pg_isready`; the API depends on a healthy PostgreSQL. Every service reads `env_file: /srv/monteluna/.env`. `deploy/env.example` lists every variable name with empty or placeholder values only (see L3 for the API names, plus `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`, `SITE_ADDRESS`, `ACME_EMAIL`, `MONTELUNA_RELEASE`), never real values.
- **VPS layout**: `/srv/monteluna/.env` (`0600`), `/srv/monteluna/releases/<release>/compose.yaml`, `/srv/monteluna/current` and `/srv/monteluna/previous` (release ids), `/srv/monteluna/releases.log` (release, SHA, UTC timestamp, outcome), `/srv/monteluna/backups/{predeploy,daily}/`.
- **Privilege model**: the operator connects as the admin user over the SSH alias; all Docker commands run inside one remote `sudo bash` session started with `ssh -t` (one sudo prompt per deploy). Images are uploaded to a temporary file first and loaded inside that session; the admin user is not added to the `docker` group (root-equivalent).
- **Deploy script** (`deploy/deploy.sh <ssh-alias> <vX.Y.Z>`): steps in the S3 order. Preflight: clean tree, existing tag, `HEAD` equal to the tag commit, local gates (`go build`, `go vet`, `go test`, govulncheck, frontend build and tests). Pre-deploy `pg_dump -Fc` to `backups/predeploy/<release>.dump` before migrations; `/app/migrate` through `docker compose run --rm api`; `up -d`; health check `GET https://$SITE_ADDRESS/api/v1/health` resolved to `127.0.0.1` on the VPS, up to 60 seconds; on failure restart `previous` for both images and exit non-zero; record the outcome; keep the current and previous images, prune older ones.
- **Backups** (`deploy/backup/`): `backup.sh` (dump to `backups/daily/`, restic backup of the dumps and the `caddy_data` volume to Cloudflare R2, `restic forget --keep-daily 7 --keep-weekly 4 --keep-monthly 6 --prune`, `restic check`), `monteluna-backup.service` + `monteluna-backup.timer` (daily, `Persistent=true`), `restore-drill.sh` (restore the latest dump into a temporary database `restore_drill`, run a sanity query on each module's `goose_db_version`, drop it, report), restic settings from `/srv/monteluna/restic.env` (`0600`) with the password in a separate `0600` file. restic itself is installed only after its own audit (A2).
- **Tests**: plain Bash test runners under `deploy/` (no new dependencies), RED first; `docker compose -f deploy/compose.yaml config` must succeed and prove only `caddy` publishes ports and every `memswap_limit` equals its `mem_limit`; every generated remote script passes `bash -n`; the deploy order (dump → migrate → up → health → rollback on failure → record) is asserted; no secret value appears in any tracked file.
